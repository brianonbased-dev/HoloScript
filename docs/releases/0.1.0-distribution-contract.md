## Identity

The first outward systems-language preview is a new distribution named **HoloScript Systems
Toolchain**, with distribution ID `holoscript-systems-toolchain` and npm identity
`@holoscript/systems@0.1.0`.

This resolves the version collision without rewriting history:

- `0.1.0` versions the toolchain distribution and its immutable artifact set;
- `@holoscript/core`, `@holoscript/cli`, the Rust crates, and hosted services keep their existing
  independent versions;
- `hs-machine-vN` remains an internal cumulative capability selector; and
- no published package, crate, wheel, image, or service version may be lowered, overwritten, or
  silently reinterpreted as the new preview.

The package is deliberately marked `planned-unpublished`. The command below is the exact future
cold-install contract, not a claim that the artifact is available today:

```powershell
npm install --global @holoscript/systems@0.1.0
holoscript --version
hs --version
holoscriptc --help
```

Publication remains forbidden until this command succeeds outside the repository and the manifest
passes with `--require-ready`.

A ready transition is evidence-bearing, not narrative. The validator requires a source commit that
resolves in the repository, existing repository-relative artifact paths, SHA-256 values that match
the artifact bytes, and parseable JSON receipts. Placeholder hashes, task prose, or planned paths
cannot satisfy that contract.

## Required distribution rails

The one release identity spans exactly three required rails:

| Rail               | Immutable identity                                     | Purpose                                                                                          |
| ------------------ | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| npm                | `@holoscript/systems@0.1.0`                            | Cold install, `holoscript`, `hs`, and `holoscriptc` entry points plus pinned component metadata. |
| Native Windows x64 | `holoscript-systems-v0.1.0-x86_64-pc-windows-msvc.zip` | Owned `holoscriptc.exe`, embedded release manifest, checksums, and license.                      |
| Bundled WASM       | `@holoscript/systems@0.1.0/wasm`                       | Portable parser/type-checker conformance component.                                              |

The candidate pins the current component lines instead of renaming them:

- `@holoscript/core@8.0.17`;
- `@holoscript/cli@8.0.11`;
- Cargo workspace `holoscript-native@3.0.0`; and
- Cargo workspace `holoscript-wasm@3.0.0`.

Changing a required pin or any artifact byte requires a new distribution version and fresh
provenance/parity receipts.

## Hosted companions and excluded rails

MCP, Absorb, and Studio are optional Railway companions. Their endpoints and compatibility probes
are declared in the manifest, but their SemVer remains independent and none is required for local
parse, validation, or compilation. A hosted outage therefore cannot redefine or revoke an installed
toolchain artifact.

The existing `holoscript` PyPI line is explicitly excluded from this first distribution identity.
It may become a declared rail in a later preview only after its version and artifact parity contract
is written. The orchestrator and LLM service are operating infrastructure, not language-distribution
artifacts.

## Supported preview surface

The candidate supports `.hs`, `.hsplus`, and `.holo` source through these bounded contracts:

- parse, validate, format, and compiler APIs from the pinned npm components;
- cumulative fail-closed native compilation through `hs-machine-v32`;
- portable parser/type-checker conformance through `holoscript-wasm`; and
- offline local operation after installation, without a private clone, founder-local files, GOLD,
  or a HoloScript service credential.

The native compiler subset is defined by the cumulative machine specifications, examples, positive
execution proofs, and negative diagnostics. A parser accepting syntax does not automatically mean
the native backend supports it.

## Known limits

`0.1.0` is not a stable API, production-readiness statement, or drop-in replacement promise. The
first native artifact targets Windows x64 only. Linux, macOS, ARM64, cross-compilation, self-hosting,
and the full wider TypeScript ecosystem surface remain outside the boundary until separately
declared and proven. Bootstrap implementation in Rust and TypeScript remains expected during the
preview.

Hosted companions have no preview SLA. Private plugins, founder-local adapters, unpinned component
versions, and undeclared host targets are unsupported.

## Compatibility and breaking changes

- A `0.x` minor release may break a documented surface only with migration notes and a changed-
  boundary list.
- A patch release must not intentionally break a documented supported surface.
- Deprecated behavior should remain for one preview minor when safety permits. Unsafe behavior may
  be removed immediately with a security migration note.
- An `hs-machine-vN` successor never changes public distribution SemVer by itself.

## Support and security boundary

The owner is the `holoscript-language-toolchain` maintainer surface. Preview issues and security
reproductions route through the repository issue tracker. Support is best effort with no uptime or
response-time SLA.

Local install, parse, validate, and compile require no HoloScript credential. Before publication,
the exact npm pack, native archive, and WASM artifact must be allowlist-inspected, secret-scanned,
checked for founder/private paths and wallet material, run through HS010/fail-closed diagnostics,
and assigned immutable SHA-256 digests.

## Rollback

Published versions remain immutable. npm rollback moves the preview dist-tag to the last verified
release; if the first preview is defective, the tag is removed and the correction becomes `0.1.1`
or later. Native artifacts retain their failed checksums, are marked withdrawn, and restore the last
verified link—or withhold the install link when no predecessor exists. Hosted companions roll back
independently and cannot require an offline artifact rewrite.

Source recovery uses a normal revert commit, preserves the failed receipt, and ships migration or
recovery notes with the corrected candidate. Force-push, artifact replacement, and version reuse are
not rollback mechanisms.

## Evaluation

Validate the boundary while it is still incomplete:

```powershell
node scripts/holo-ci/check-systems-preview-release.mjs
```

The publication gate is intentionally stricter and currently exits non-zero:

```powershell
node scripts/holo-ci/check-systems-preview-release.mjs --require-ready --json
```

Every required gate, current disposition, evidence path, verification command, and remaining action
is carried in the manifest. A future readiness baseline may change **NOT READY** only after that
machine check reports `ready: true` for the exact candidate artifacts.
