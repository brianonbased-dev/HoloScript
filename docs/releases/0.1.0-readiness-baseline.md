# HoloScript Systems Toolchain `0.1.0` readiness baseline

Date: 2026-07-22<br>
Disposition: **READY CANDIDATE — NOT YET PUBLISHED**<br>
Scope: first outward preview under the
[native machine release ladder](../spec/native-machine-release-ladder.md).

The candidate is the `holoscript-systems-toolchain` distribution, published on npm as
`@holoscript/systems@0.1.0`. It presents HoloScript as a general-purpose semantic systems
programming language: a pinned CLI and language core, the `hs-machine-v32` native compiler, and a
portable WASM parser/type-checker. Hosted MCP, Absorb, and Studio remain optional, independently
versioned companions. PyPI is excluded from this first distribution identity.

The machine-readable authority is
[`systems-preview-release-manifest.json`](../../scripts/holo-ci/systems-preview-release-manifest.json),
and the consumer boundary is defined in the
[`0.1.0` distribution contract](0.1.0-distribution-contract.md). All required gates now pass, so
the candidate is authorized for publication. This baseline does not claim that npm or a GitHub
release already serves it; publication and registry readback are the next state transition.

## Consumer proof

A fresh temporary project installed the exact local tarball without repository access. The probe
verified:

- package identity `@holoscript/systems@0.1.0`;
- exact dependencies `@holoscript/core@8.0.17` and `@holoscript/cli@8.0.11`;
- the `holoscript`, `hs`, and `holoscriptc` command surfaces;
- parse and validation of all 25 corpus programs through the packed WASM runtime; and
- native compilation and execution of all 25 programs, each returning the declared exit code 5.

The exact packed npm, native, and WASM artifacts passed allowlist and secret-shaped-material scans.
No founder-local path, credential, private key, wallet material, auth cache, or unintended source
map was detected.

## Publication transition

Publish the exact tarball under the npm `preview` dist-tag, attach the immutable native and WASM
artifacts to the matching source release, then run the same repo-less probe against
`@holoscript/systems@0.1.0` from the public registry. Only after those readbacks succeed may the
manifest move from `candidate-built` to `published`.
