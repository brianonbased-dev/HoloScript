# HoloScript `0.1.0` outward-preview readiness baseline

Date: 2026-07-19  
Disposition: **NOT READY**  
Scope: first evidence baseline under the
[native machine release ladder](../spec/native-machine-release-ladder.md), not authorization to
publish, deploy, tag, or describe an existing package as the new `0.1.0` preview.

The non-conflicting boundary is now defined by the
[`HoloScript Systems Toolchain 0.1.0` distribution contract](0.1.0-distribution-contract.md) and
its machine-readable
[`systems-preview-release-manifest.json`](../../scripts/holo-ci/systems-preview-release-manifest.json).
The manifest remains `defined-not-ready`; this baseline therefore remains **NOT READY**.

## Version-line finding

The `0.1.0` rule cannot be applied by lowering the versions of existing package identities. Public
HoloScript artifacts predate this release canon and already occupy several independent lines:

- the root workspace is `6.1.3`;
- the npm readiness manifest contains 19 already-published packages spanning `0.x`, `1.x`, `2.x`,
  `6.x`, and `8.x`;
- PyPI currently serves `holoscript 6.0.7` and `holoscript-trait-inference 0.1.0`; and
- sampled live services report independent versions, including MCP `8.0.13`, Absorb `6.1.1`, and
  the LLM service `1.0.0`.

These are legacy public lines, not proof that the newly canonized general-purpose systems-language
preview gate has passed. The new boundary is `holoscript-systems-toolchain`, with planned npm
identity `@holoscript/systems@0.1.0`. It pins existing component versions and declares required,
optional, and excluded rails without resetting them. Existing registry versions must never be
overwritten, reset, or silently reinterpreted.

```powershell
# V31 compiler/runtime
cargo test -p holoscript-native
cargo test -p holoscript-wasm
cargo clippy -p holoscript-native -p holoscript-wasm --all-targets -- -D warnings
cargo run --release -p holoscript-native --bin holoscriptc -- \
  examples/native/compositional-borrow-summary-exit-five.hs -o <temp>/v31-proof.exe

# Existing package and rail gates
node scripts/holo-ci/check-systems-preview-release.mjs --json
node scripts/holo-ci/check-systems-preview-release.mjs --check-services --json

node scripts/holo-ci/check-package-stewardship.mjs
node scripts/holo-ci/check-registry-cold-start.mjs \
  --package @holoscript/core@latest --probe core-holo-webgpu --json
node scripts/holo-ci/check-registry-cold-start.mjs \
  --package @holoscript/mcp-server@latest --probe mcp-server-sizing --json
corepack pnpm run check:pypi-live-consumption
node scripts/check-version-policy.js
```

The package-architecture and package-stewardship commands intentionally fail for the gaps recorded
above. A green readiness declaration must rerun them and replace those failures with receipts.

## Required next closure

1. Remove or prove the four unconsumed npm candidates and add the three missing steward records.
2. Build `@holoscript/systems@0.1.0`, the declared native Windows x64 archive, and the bundled WASM
   runtime; inspect their packed contents and run
   candidate-specific secret and lexical-firewall gates.
3. Run cold install/invocation, parity, hosted-companion compatibility, and rollback readback for
   every declared rail.
4. Emit a new dated baseline. Only a fully green successor may authorize the first outward preview.
