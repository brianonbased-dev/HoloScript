# HoloScript `0.1.0` outward-preview readiness baseline

Date: 2026-07-19  
Disposition: **NOT READY**  
Scope: first evidence baseline under the
[native machine release ladder](../spec/native-machine-release-ladder.md), not authorization to
publish, deploy, tag, or describe an existing package as the new `0.1.0` preview.

## Version-line finding

The `0.1.0` rule cannot be applied by lowering the versions of existing package identities. Public
HoloScript artifacts predate this release canon and already occupy several independent lines:

- the root workspace is `6.1.3`;
- the npm readiness manifest contains 19 already-published packages spanning `0.x`, `1.x`, `2.x`,
  `6.x`, and `8.x`;
- PyPI currently serves `holoscript 6.0.7` and `holoscript-trait-inference 0.1.0`; and
- sampled live services report independent versions, including MCP `8.0.13`, Absorb `6.1.1`, and
  the LLM service `1.0.0`.

These are legacy public lines, not proof that the newly canonized general-purpose systems-language
preview gate has passed. Before an outward preview can be named `0.1.0`, the release lane must define
one new, non-conflicting distribution boundary or explicitly supersede the first-preview numbering
rule for an existing identity. Existing registry versions must never be overwritten, reset, or
silently reinterpreted.

## Gate matrix

| `0.1.0` evidence gate | Status | 2026-07-19 evidence |
| --- | --- | --- |
| Named consumer boundary | **BLOCKED** | No manifest identifies which package, CLI, native toolchain bundle, or service is the new general-purpose systems-language `0.1.0` product. The existing npm manifest is named as a v1 fleet lane and contains 19 heterogeneous packages. |
| Supported features and known limits | **PARTIAL** | Native contracts v0-v31 and their boundaries are specified. A release-level supported subset and consolidated consumer limitations document for the new distribution do not yet exist. |
| Cumulative machine conformance | **PASS (native slice)** | `cargo test -p holoscript-native` passed 76 integration/unit tests plus three library tests; `cargo test -p holoscript-wasm` passed 206 tests. This is not a claim that every workspace package passed its full suite. |
| Deterministic artifact and provenance | **PASS (v31 slice)** | V31 compiled identical object bytes twice. Release-profile `holoscriptc` selected `hs-machine-v31`, emitted object SHA-256 `867349d4c5b980f2ee40630975f2598378baf111020fcbfef6fb77fa790da432`, and the optimized x64 executable exited 5. |
| Cold npm consumption | **PASS (sampled current rails)** | Repo-less isolated installs passed for `@holoscript/core@8.0.16` and `@holoscript/mcp-server@8.0.13`. Core parsed and compiled HoloScript to WebGPU with output SHA-256 `d3990081c88b42735183e48d51da647e706e08ea248b9b5f220a04434f3426c5`; MCP sizing imports passed. This does not prove a new `0.1.0` artifact. |
| Cold PyPI consumption | **PASS (current rails)** | Fresh virtual environments installed and imported `holoscript 6.0.7` and `holoscript-trait-inference 0.1.0`; the trait-inference console probe passed. |
| Registry version/dependency closure | **PASS (current npm manifest)** | The live npm readiness checker found all 19 candidates already published at their local versions with no dependency-closure errors. |
| Package architecture | **FAIL** | `@holoscript/agent-protocol`, `@holoscript/llm-provider`, `@holoscript/snn-webgpu`, and `@holoscript/holoembed` are candidates without fleet consumption or a declared release-candidate public API canary. |
| Package stewardship | **FAIL** | Steward records are missing for `@holoscript/agent-protocol`, `@holoscript/snn-webgpu`, and `@holoscript/holoembed`. |
| Publish and secret-safe boundary | **PARTIAL** | The publish-surface checker passed 58 public packages as allowlisted and free of detected mojibake. The compiler/WASM suites retain HS010 lexical-firewall tests. A candidate-specific packed-artifact secret scan and explicit threat/support boundary remain required. |
| Railway readback | **PASS (health only)** | All five declared health targets returned HTTP 200: orchestrator, MCP, Absorb, LLM service, and Studio. No rollback drill, artifact-parity proof, or `0.1.0` deployment exists. |
| Preview compatibility policy | **PARTIAL** | The release ladder states that `0.x` is unstable and not a v1 promise. The selected distribution still needs a concrete breaking-change, deprecation, and upgrade policy. |
| Release owner, support, and rollback | **BLOCKED** | Package stewardship exists for many current rails, but no owner/support/rollback contract is attached to the new `0.1.0` systems-language boundary. |
| Cross-rail parity | **BLOCKED** | npm, PyPI, Railway, Cargo/native contracts, and the workspace root use independent versions and artifacts. The preview must declare which rails share one release identity and how parity is verified. |

  examples/native/compositional-borrow-summary-exit-five.hs -o <temp>/v31-proof.exe

node scripts/holo-ci/check-registry-cold-start.mjs \
  --package @holoscript/core@latest --probe core-holo-webgpu --json
node scripts/holo-ci/check-registry-cold-start.mjs \
  --package @holoscript/mcp-server@latest --probe mcp-server-sizing --json
corepack pnpm run check:pypi-live-consumption
node scripts/check-version-policy.js

The package-architecture and package-stewardship commands intentionally fail for the gaps recorded
above. A green readiness declaration must rerun them and replace those failures with receipts.

## Required next closure

1. Name the new outward product boundary and decide how it coexists with legacy public version lines.
2. Write its supported-feature, known-limit, install, support, breaking-change, and rollback contract.
3. Remove or prove the four unconsumed npm candidates and add the three missing steward records.
4. Build the exact candidate artifacts, inspect their packed/wheel/container contents, and run
   candidate-specific secret and lexical-firewall gates.
5. Run cold install/invocation and rollback readback for every rail declared part of the same release.
6. Emit a new dated baseline. Only a fully green successor may authorize the first outward preview.
