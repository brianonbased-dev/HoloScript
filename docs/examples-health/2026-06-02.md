## Failure Patterns

### Pattern A — Comma-separated inline blocks (most common)

Properties inside `environment {}`, `light {}`, `material {}`, `post_processing {}` blocks are written with comma separators on a single line. The current parser requires line-separated (no commas) properties.

**Old (fails):**

```holo
environment { skybox: "gradient", ambient_light: 0.35, shadows: true }
```

**Current valid:**

```holo
environment {
  skybox: "gradient"
  ambient_light: 0.35
  shadows: true
}
```

Affects: `quickstart/1-floating-cyan-orb`, `quickstart/2-red-cube-teal-button`, `quickstart/3-ball-ramp`, `traits/audio-spatial-ambient-voice-reverb`, `showcase/physics-playground`

### Pattern B — Unquoted composition names

`composition IdentifierName {` now fails with "Expected string, got IDENTIFIER". Names must be quoted.

**Old (fails):**

```holo
composition ParticleEmittersShowcase {
```

**Current valid:**

```holo
composition "ParticleEmittersShowcase" {
```

Affects: `weather/01-particle-emitters`, `narrative/03-investigation-mystery`, `emotion/01-emotional-systems`, `procedural/01-terrain-generation`, `lighting/01-light-types`, `physics/advanced-physics-showcase`

### Pattern C — Nested block as inline property value

`skybox: { type: "gradient", top: "#0a0a14" }` style inline-object values fail.

Affects: `getting-started/hello-world`, `showcase/realistic-forest` (articulation/hinge sub-blocks), `showcase/physics-playground` (arrow syntax in input domain)

### Pattern D — `@trait` annotation inside domain block

Using `@traitname` annotation syntax inside a block context (not at the entity level) triggers "Expected identifier, got AT".

Affects: `traits/audio-spatial-ambient-voice-reverb`
