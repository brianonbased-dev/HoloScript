### P2 — Code Quality / Style

#### P2-1 — `execSync` with string interpolation for tsx runner
**File:** `examples/gold-game/verify-all.mjs:113`
**Commit:** `ed6b016a`

```js
execSync(`"${tsx}" "${target}"`, { stdio: 'ignore', cwd: repoRoot });
```

`tsx` and `target` are both resolved from controlled paths (`node_modules/.bin/tsx` and `join(here, rel)` where `rel` is a static GATES config string). There is no external user input flowing into these interpolations, so this is not an exploitable injection. However, the pattern is fragile — if `tsx` path ever contains embedded quotes or special characters on an unusual platform, it would break. The node branch two lines later correctly uses `execFileSync` with an array. The tsx branch uses `execSync` with a string only because the tsx `.cmd` shim on Windows requires shell execution, and the author comments this.

**Recommendation:** Add a comment explicitly noting this is Windows-cmd-shim-required, and validate that `tsx` does not contain shell-special characters at startup. Risk is low (tooling/examples code, not production).

#### P2-2 — `any` types in `OnnxNodeInferenceAdapter`
**File:** `packages/core/src/traits/engines/onnx-adapter.ts:286,288`
**Commit:** `9c44a606`

```ts
// eslint-disable-next-line @typescript-eslint/no-explicit-any
private session: any = null;
// eslint-disable-next-line @typescript-eslint/no-explicit-any
private ort: any = null;
```

These are dynamic imports of `onnxruntime-node`, an optional native dependency with no guaranteed ambient types at compile time. The `eslint-disable` annotations show the author was aware. The correct fix is `unknown` with a runtime type guard narrowing before `.run()`. Since this is behind an optional-dependency dynamic import and the `OnnxNodeInferenceAdapter` class is documented as the server-side async path (not default), the blast radius is low.

**Recommendation:** Replace `any` with `unknown` and add a `isOrtSession(x: unknown): x is { run(...) }` type guard, or import the ORT type definitions conditionally.
