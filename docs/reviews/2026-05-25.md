### P1 — Frozen-primary commit guard path is OS-specific

- **Commit:** `4ed02adf` — `fix(hooks): durable frozen-primary commit guard`
- **File:** `scripts/install-agent-pre-commit.sh:39`
- **Issue:** The guard condition is:
  ```sh
  if [ "$__fm_root" = "c:/users/josep/documents/github/holoscript" ] && ...
  ```
  On Linux (including CI containers and HoloScript remote sessions) `git rev-parse
--show-toplevel` returns a POSIX path. The equality check is always false outside
  Windows. The freeze guard is a no-op on every non-Windows system — including the
  environment running this review.
- **Risk:** The stranded-commit problem the guard was introduced to solve is still
  possible for any agent running in a Linux worktree on `main` or `codex/*`.
- **Fix options:**
  - Drop the root-path check; key only on the git remote URL or a `.frozen-primary`
    sentinel file: `[ -f "$(git rev-parse --git-dir)/holoscript-frozen-primary" ]`
  - Or normalize the path before comparison:
    `__fm_root="$(... | tr '[:upper:]' '[:lower:]' | tr '\\\\' '/')"` and add a
    Linux canonical path as a second `||` branch.

  mocks `existsSync` and asserts each of the three resolution tiers (explicit env,
  models-dir env, repo-root walk) returns the expected path or `undefined`.

### P3 — Base64 regex does not enforce 4-byte length alignment

- **Commit:** `476b35f2` — `feat(studio): thread measured depth + device pose through
the scan transport`
- **File:** `packages/studio/src/lib/native-camera-live-scan.ts:105`
- **Issue:** The validation regex `/^[A-Za-z0-9+/]+={0,2}$/` accepts strings whose
  length is not divisible by 4 (e.g. `"YQ="` — 3 chars). Node.js `Buffer.from(...,
'base64')` is lenient and silently skips invalid chars, potentially yielding fewer
  bytes than expected. The downstream byte-length check (`bytes.byteLength !== expected`)
  catches this case at runtime, so there is no exploitable path. But the regex
  advertises stronger validation than it provides.
- **Note:** Same pattern appears at line 160 for `rgbBase64` (pre-existing).
- **Fix (low priority):** Add a length-alignment check after the regex:
  ```ts
  if (raw.length % 4 !== 0) throw new Error('depthBase64 length must be divisible by 4');
  ```
  Or use `atob`/`Buffer.from` inside a try-catch and rely solely on the byte-length
  guard (remove the regex entirely since it adds no real safety).
