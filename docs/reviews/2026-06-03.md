### P0-A · Cross-user asset data leak in `/api/assets` — FIXED in `1ec7af3c`

**Status:** Fixed in this batch. Board task filed as audit record (credentials unavailable — payload below).
**Commit:** `1ec7af3c`
**File:** `packages/studio/src/app/api/assets/route.ts`
**Issue:** `GET /api/assets` was unauthenticated and queried the assets table with **no `ownerId` filter** — any caller received every user's uploaded assets merged with the public seed catalog. `POST /api/assets` updated assets by `id` with no ownership check, allowing any logged-in user to overwrite another user's asset record.

**Fix (already applied):** `GET` now resolves the session and returns DB uploads only where `ownerId = session.user.id`. `POST` scopes the `WHERE` clause to `id AND ownerId = userId`; non-owners get an indistinguishable 404.

**Residual gap:** Neither endpoint is covered by an integration test that verifies cross-user isolation (the fix is correct but untested in that dimension). A follow-up test that asserts user B's assets are absent from user A's response would close this permanently.

### P2-A · `/verify-cael` POST endpoint — no rate limiting

**Commit:** `baa59dec`
**File:** `packages/mcp-server/src/http-server.ts` (around the `/verify-cael` block)
**Issue:** The new public `/verify-cael` endpoint is intentionally unauthenticated (correct for external repro). The `POST` path accepts up to 10 MB of `traceJSONL` and calls `handleSimulationTool('verify_cael_trace', …)` which runs a hash-chain verification + deterministic-replay pass. No rate limiter is applied (the file's existing per-IP OAuth rate limiter, line ~222, is not extended to this route). An adversary can hammer the endpoint with crafted 10 MB payloads at maximum concurrency, exhausting the Node.js event loop on the mcp-server process.

**Mitigations already present:** 10 MB body cap in `parseJsonBody`; the simulation replay is CPU-bounded (no GPU calls); no database or external service writes.

**Recommended fix:**

```typescript
// Re-use the existing rateLimit() helper; add before the verifyCaelResult call:
const rl = rateLimit(req, 'verify-cael', 30); // 30 req/min per IP
if (rl.remaining < 0) {
  res.writeHead(429, { 'Retry-After': String(Math.ceil((rl.resetAt - Date.now()) / 1000)) });
  res.end(JSON.stringify({ error: 'Rate limit exceeded. Retry after reset.' }));
  return;
}
```

### P3-A · `holo-ci-tools.ts` — hardcoded fallback production orchestrator URL

**Commit:** `8323a923`
**File:** `packages/mcp-server/src/holo-ci-tools.ts:278`
**Code:**

```typescript
process.env.MCP_ORCHESTRATOR_URL || 'https://mcp-orchestrator-production-45f9.up.railway.app';
```

**Issue:** The Railway URL is a deployment-specific hostname embedded in source. If the orchestrator service is redeployed to a new Railway project, `holo_ci_dispatch` silently targets a dead URL until `MCP_ORCHESTRATOR_URL` is set. The Railway URL is also now publicly visible in any clone of the repo. No credentials are exposed (the key is pulled separately from env), but it ties the code to one specific deployment identifier.

**Fix:** Move the default URL to an env-driven `.env.example` entry and document the required variable. Alternatively, the fallback could point at a stable custom domain (e.g. `mcp-orchestrator.holoscript.net`) independent of the Railway slug.

### P3-B · `holo-ci-tools.ts` gate catalog is a manual port — divergence risk

**Commit:** `8323a923`
**File:** `packages/mcp-server/src/holo-ci-tools.ts:46` (comment)
**Issue:** The comment explicitly notes the catalog is "duplicated rather than imported because HoloScript and ai-ecosystem are separate repos." This is an intentional trade-off, but there is no mechanism to detect when `ai-ecosystem/scripts/holo-ci/gates.mjs` (the canonical source) diverges from the TS port. A gate added or renamed in `gates.mjs` will silently be absent from `holo_ci_dispatch` until manually synced.

**Recommendation:** Add a comment referencing the canonical file and a note in `CLAUDE.md` or the HoloCI docs to sync both when gates change. Optionally, add a CI snapshot test that builds the workload for both repos with both profiles and asserts the gate IDs match an expected list — this would at least fail loudly when the TS port goes stale.
