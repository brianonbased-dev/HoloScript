### P2-1 — Intelligence feed: no content length cap
**Commit**: `9d74391d` `feat(holomesh): support intelligence feed items on POST /feed`  
**File**: `packages/mcp-server/src/holomesh/routes/board-routes.ts`

The new `kind=intelligence` branch in `POST /feed` accepts arbitrary-length `content`:

```typescript
const content = typeof body.content === 'string' ? body.content.trim() : '';
if (!content) {
  json(res, 400, { error: 'Missing content for intelligence feed item' });
  return true;
}
// → content is stored as-is in the in-memory teamFeedStore with no length cap
```

The broadcast truncates to 200 chars (`content.slice(0, 200)`) but the stored `item.content` is unbounded. The existing hologram path calls `validateHologramFeedInput(hash, shareUrl)` which validates field lengths; intelligence content has no equivalent guard. A misconfigured or malicious authenticated agent can fill `teamFeedStore` with multi-megabyte strings per request (cap is 200 items, each potentially unbounded).

**Fix**: Add a max-length guard before constructing the item, e.g.:
```typescript
if (content.length > 10_000) {
  json(res, 400, { error: 'content too long (max 10 000 chars)' });
  return true;
}
```

### P2-2 — WebhookOutTrait: SSRF via runtime event URL
**Commit**: `d453e7ce` `feat(core): wire Tier-4 integration traits + spec remaining stubs`  
**File**: `packages/core/src/traits/WebhookOutTrait.ts`

`WebhookOutTrait` now makes real outbound HTTP calls, but the target URL comes from the runtime `webhook:send` event payload, not from the static trait config:

```typescript
const url = (event.url as string) ?? '';
// ...
fetchWithRetry(url, { method: 'POST', ... }, config.max_retries, config.timeout_ms)
```

Any scene or logic graph that fires `webhook:send` can direct these requests to arbitrary hosts, including internal services (`http://localhost:6379`, `http://169.254.169.254/latest/meta-data/`, etc.). The Slack/Discord/SlackAlert traits use a static `config.webhook_url` from scene configuration (lower risk), but `WebhookOutTrait` takes the URL from dynamic event data.

This is an SSRF vector when traits execute in a server-side context (Railway deploy, MCP server, etc.).

**Fix options**:
- Validate URL scheme and host against a configurable allowlist before calling `fetchWithRetry`
- Or add a `url_allowlist` field to `WebhookOutConfig` and reject events whose URL doesn't match
- Minimum: reject non-HTTPS URLs and private IP ranges at the boundary

### P2-3 — NodeGraphCompiler.traceDownstream: potential infinite loop on cyclic input
**Commit**: `2d6415bb` `fix(logic): MathMultiply b=0 emits 1 instead of 0`  
**File**: `packages/core/src/logic/NodeGraphCompiler.ts`

The `traceDownstream` method was moved and rewritten. The new implementation does not add `startId` to the `visited` set before processing:

```typescript
// New (line 127–141)
private traceDownstream(startId: string, graph: NodeGraph): string[] {
  const visited = new Set<string>();
  const queue = [startId];
  while (queue.length > 0) {
    const id = queue.shift()!;        // startId dequeued but never added to visited
    const connections = ...filter(c => c.fromNode === id);
    for (const conn of connections) {
      if (!visited.has(conn.toNode)) {
        visited.add(conn.toNode);
        queue.push(conn.toNode);
      }
    }
  }
  return Array.from(visited);
}
```

The old implementation added `current` to `visited` before processing its outgoing connections, preventing re-enqueuing on back-edges. The new version doesn't mark `startId` as visited, so a back-edge from any reachable node back to `startId` would re-enqueue it, starting infinite recursion. HoloScript logic graphs are expected to be DAGs, so this is unlikely to trigger in practice — but the invariant is implicit and the guard is gone.

Additionally, `getConnections().filter(c => c.fromNode === id)` is O(total-connections) per BFS step vs the existing `graph.getConnectionsFrom(id)` which is O(connections-from-node). The old method is still available on `NodeGraph` (line 351); the `as any` cast is unnecessary.

**Fix**: Initialize `visited` with `startId` before the loop, and call `graph.getConnectionsFrom(startId)` directly (it's typed, no `as any` needed):
```typescript
const visited = new Set<string>([startId]);
// ...
const connections = graph.getConnectionsFrom(id);
```

### P3-2 — CI bootstrap: `$CI_SEAT` unescaped in JSON body
**Commit**: `bf5c4e35` `feat(holo-ci): add CI seat registration to bootstrap script`  
**File**: `scripts/mesh-deploy/ci-runner-bootstrap.sh`

`$CI_SEAT` is derived from `hostname` and interpolated directly into a JSON string:
```bash
-d "{\"id\":\"$CI_SEAT\", ...}"
```

If the hostname contains a `"` or `\` (unusual but possible via env var override), the JSON body becomes malformed and the registration silently fails. Use `jq -n --arg id "$CI_SEAT" '{"id":$id,...}'` or equivalent to produce safe JSON.

**Commit**: `2d6415bb` `fix(logic): MathMultiply b=0 emits 1 instead of 0`  
**File**: `packages/core/src/logic/NodeGraphCompiler.ts`

`CompiledDirective.type` was `'lifecycle' | 'state' | 'event'`; it is now `'state' | 'event' | 'update' | 'compute'`.
