## P1 — Broken Invariant (FIXED INLINE)

### P1-1 · LSP bin stub: wrong dist target (commit `bb3828b3`)

**File:** `packages/lsp/bin/holoscript-lsp.cjs:3`
**Issue:** Bin stub changed to `require('../dist/cli.cjs')` but LSP's tsup config has no `cli.ts` entry — only `src/server.ts` / `src/debugServer.ts` with `format: ['cjs']`. The file `dist/cli.cjs` does not exist; `holoscript-lsp` would crash on startup with "Cannot find module".
**Fix applied:** Changed to `require('../dist/server.js')` (correct single-CJS-format output from tsup).

### P1-2 · Formatter + Linter bin stubs: `require()` on ESM output (commit `bb3828b3`)

**Files:** `packages/formatter/bin/holoscript-format.cjs:3`, `packages/linter/bin/holoscript-lint.cjs:3`
**Issue:** Stubs changed from `import(pathToFileURL(target).href)` (dynamic ESM import, works for ESM output) to `require('../dist/cli.cjs')`. Both packages have `format: ['esm']` in their tsup configs; they produce `dist/cli.js` (ESM syntax). A `require()` of ESM produces either `ERR_REQUIRE_ESM` or `SyntaxError` depending on Node.js version. The old dynamic-import pattern was the correct approach.
**Fix applied:** Restored dynamic-import pattern targeting `dist/cli.js`.

## P2 — Code Quality

### P2-1 · `isolate-spawn.mjs`: Hardcoded Windows absolute path (commit `8a0112d3`)

**File:** `scripts/agent-isolation/isolate-spawn.mjs:21`
**Issue:** `const PRIMARY = 'c:/users/josep/documents/github/holoscript'` — on Linux/macOS `norm(root) !== PRIMARY` is always true, so the script silently exits as a no-op. When activated fleet-wide (per README: "ACTIVATION IS FLEET-COORDINATED") any non-Windows agent gets no isolation enforcement with no warning. Should be driven by an env var or detect the frozen-primary state structurally (e.g. an env flag `HOLOSCRIPT_FROZEN_PRIMARY=true`).
**No fix applied** — the script is intentionally not yet wired; this is a pre-activation design gap, not a runtime regression.

### P2-2 · `board-routes.ts`: `as any` cast extended to new event types (commit `95ea303b`)

**File:** `packages/mcp-server/src/holomesh/routes/board-routes.ts:1699,1769`
**Issue:** `type: 'founder:approval' as any` and `type: 'founder:approval:update' as any` — the new founder-approval broadcast events are not in the `TeamRoomEvent` type union, requiring `as any` casts. The pattern pre-existed (lines 676, 752, 1217, 1582) but is being extended rather than fixed. The union should be widened to include the new event types, removing all `as any` casts from broadcast calls.

### P2-3 · `HoloEmbedProvider.ts`: empirical weight undocumented in code (commit `3054df0f`)

**File:** `packages/absorb-service/src/engine/providers/HoloEmbedProvider.ts:72`
**Issue:** `const STRUCTURAL_WEIGHT = 0.35` is tuned from Paper 26 Table 2 experiments (recall@10 90%→100%) but the rationale lives only in the commit message. If this constant is re-tuned without the context, the embedding quality impact won't be obvious. A one-line comment referencing the paper/metric would be sufficient.
