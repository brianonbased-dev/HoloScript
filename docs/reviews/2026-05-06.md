## Findings

### P2-A — `/approve-via-tx` has no batch-size cap; unbounded outbound RPC calls

- **Commit**: `6f0cead`
- **File**: `packages/mcp-server/src/holomesh/routes/attestation-routes.ts`
- **Severity**: P2 (resource exhaustion via self-inflicted DoS)

The new `POST /api/identity/attestation/approve-via-tx` endpoint accepts either a single envelope or a batch via `attestations_via_tx: [...]`. For each envelope it makes **two parallel** `eth_getTransactionByHash` / `eth_getTransactionReceipt` calls to the Base mainnet RPC. There is no cap on `envelopes.length`.

A founder-authenticated request with 500 envelopes would fire 1,000 outbound RPC calls simultaneously, exhausting the RPC provider's rate window and potentially timing out the entire HoloMesh process. The `requireAuth + isFounder` guard prevents unauthorized use, but does not protect against accidental or adversarial over-batching from an authenticated founder session.

**Recommended fix** — add a guard before the loop:

```ts
const MAX_BATCH = 50;
if (envelopes.length > MAX_BATCH) {
  json(res, 400, { error: `batch too large (max ${MAX_BATCH}, got ${envelopes.length})` });
  return true;
}
```

### P2-B — `estimate_task_duration` MCP tool reads caller-supplied filesystem paths without boundary enforcement

- **Commit**: `435b53d`
- **File**: `packages/mcp-server/src/tools/estimate_task_duration.ts`
- **Severity**: P2 (OWASP A01 path traversal — scoped to MCP-authenticated sessions)

`estimateTaskDuration()` accepts `dataPath` and `sourceRoot` from the MCP tool call arguments. Both are passed to `firstExistingFile()` → `resolve(p)` → `existsSync` / `statSync` / `readFileSync` with **no boundary check**. A caller can supply `dataPath: "../../../../etc/some-world-readable.json"` and the tool will read and surface that file's contents if it parses as JSON matching `AgentTimeArtifact`.

Exploitability is limited to MCP-authenticated clients, but prompt-injection via LLM-driven tool calls is a realistic vector (the tool is surfaced to AI agents). The GOLD drive and previous review flagged a similar pattern (`fe186f8`, 2026-05-05 R-02) in `@holoscript/std/fs` — that fix should serve as the model here.

**Recommended fix** — add a `resolvedRoot.startsWith(allowedBase)` guard in `firstExistingFile`:

```ts
const ALLOWED_BASE = resolve(homedir(), '.ai-ecosystem');
function firstExistingFile(paths: Array<string | undefined>): string | null {
  for (const p of paths) {
    if (!p) continue;
    const resolved = resolve(p);
    if (!resolved.startsWith(ALLOWED_BASE + path.sep) && resolved !== ALLOWED_BASE) continue;
    try {
      if (existsSync(resolved) && statSync(resolved).isFile()) return resolved;
    } catch {
      /* skip */
    }
  }
  return null;
}
```

### P3-A — Test-only `as any` casts in `protocol-agent.test.ts` and `PhysicsWorld.test.ts`

- **Commit**: `dab2c7c`
- **Files**: `packages/framework/src/__tests__/protocol-agent.test.ts`, `packages/runtime/src/physics/PhysicsWorld.test.ts`
- **Severity**: P3 (style — test files only, not production code)

Five `as any` casts were added in test files:

```ts
const r = (await waitForEvent(ctx, 'jwt:issued')) as any;
const token = ((await waitForEvent(ctx, 'jwt:issued')) as any).token;
(globalThis as any).BroadcastChannel = MockBroadcastChannel;
set: vi.fn(function (this: any, x: number, y: number, z: number) {
```

These are test files so the risk is low, but CLAUDE.md's preference for `unknown` over `any` applies codebase-wide. Alternatives:

- `waitForEvent` result → type the return of `waitForEvent` as a specific union or use `unknown` + a type guard
- `globalThis as any` → `(globalThis as Record<string, unknown>).BroadcastChannel = MockBroadcastChannel`
- `vi.fn(function (this: any, ...)` → the `this` binding can be typed with `vi.fn<Parameters, ReturnType>()` instead

Not blocking, but worth a follow-up cleanup pass on the test helpers.

### P3-B — `persistCaelAuditRecord` test-environment gate leaks into production path

- **Commit**: `dab2c7c`
- **File**: `packages/mcp-server/src/holomesh/state.ts`
- **Severity**: P3 (test concern bleeding into production code)

```ts
function persistCaelAuditRecord(handle: string, record: CaelAuditRecord): void {
  if (
    process.env.NODE_ENV === 'test' &&
    process.env.HOLOMESH_TEST_DISABLE_CAEL_AUDIT_PERSISTENCE === '1'
  ) {
    return;
  }
  // ... production path
}
```

Env-var test gates inside production functions are a code smell — they make it impossible to reason about production behavior independently of test configuration and they accumulate over time. Preferred pattern: inject a `persistFn` dependency or use vitest's `vi.mock('../holomesh/state.js')` to replace the module-level side-effect entirely in the test that needs it, keeping the production function unconditional.
