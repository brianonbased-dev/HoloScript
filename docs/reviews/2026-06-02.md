### P2-A · Empty `.catch()` in `NetworkedTraitHandler.onAttach` lacks inline justification

**Commit:** `e2681b24`
**File:** `packages/core/src/traits/NetworkedTraitHandler.ts:141`
**Code:**
```ts
void import('@holoscript/mesh').then((m) => { _mesh ??= m; }).catch(() => {});
```
**Issue:** The empty `.catch(() => {})` silently swallows import failures. The rationale (optional peer — `ERR_MODULE_NOT_FOUND` is safe to drop) is explained at line 37 but not inline on line 141 where a future reader sees the catch. Without the comment, this reads as an oversight rather than an intentional choice. A maintainer who doesn't trace back to the file header may add error logging (e.g. `console.warn`) that would surface spurious warnings in mesh-optional deployments, or remove the catch entirely thinking it was a mistake.
**Fix:** Add `// optional peer — safe to ignore` on the same line, or extract a named `swallowOptionalPeerImportError` handler. One of:
```ts
void import('@holoscript/mesh').then((m) => { _mesh ??= m; }).catch(() => {}); // optional peer — ERR_MODULE_NOT_FOUND expected when mesh not installed
```
