### P2-A · `/api/fleet-metrics` missing rate limiting

**Commit:** `acdd2a69`
**File:** `services/llm-service/src/server.ts:321`
**Issue:** The new `GET /api/fleet-metrics` endpoint is registered without `rateLimiter.middleware()`. Every other data-returning endpoint (`/api/chat`, `/api/generate`) uses the rate limiter. The endpoint is protected by `authMiddleware` in production (returns 401 without Bearer token when `NODE_ENV=production`), so unauthenticated abuse is blocked, but an authenticated user can hammer it without any backpressure. Pattern inconsistency also risks copy-paste omission in future endpoints.
**Fix:** Add `rateLimiter.middleware()` as a first argument, same as `/api/chat`:

```typescript
// services/llm-service/src/server.ts:321
app.get('/api/fleet-metrics', rateLimiter.middleware(), (req: Request, res: Response) => {
```

**Issue:** AST parameters typed as `any` (`ast: any`, `t: any`, `obj?.traits?.find((t: any) => ...)`). This is a build script (not shipped code), but it bypasses TypeScript's safety on the AST shape. If `@holoscript/core` exports `HoloAst` or similar types they should be used here.

### P3-A · Token estimation diverges for non-ASCII content

**Commits:** `acdd2a69`, `b738550c`, `92040b2f`
**Files:** `services/llm-service/src/services/FleetMetrics.ts`, `packages/mcp-server/src/ollama-client.ts`, `packages/studio/src/lib/brittney/fleetMetrics.ts`
**Issue:** All three telemetry implementations use `Math.ceil(length / 4)` (1 token ≈ 4 chars) for prompt/completion token estimation. This is intentional and the commit messages acknowledge it ("rough estimate"). However, for CJK, emoji, or multi-byte content the estimate is 2–4× off. Since the data feeds a self-hosted fleet sizing decision, systematic undercounting on non-ASCII workloads could produce a misleading utilization crossover.
**Risk:** Low (Phase-0 capacity planning only; orders-of-magnitude accuracy sufficient at this stage).
**Note:** Noted for Phase-1 — wire actual token counts from provider responses when available (Anthropic returns `usage.input_tokens`, OpenRouter returns `usage`).

### P3-B · Narupa optional-capability cast is fragile

**Commit:** `f8ace1e5`
**File:** `packages/plugins/scientific-plugin/src/narupa-orchestrator.ts:173`
**Issue:** The fix casts `this.processManager` as `{ getAvailableCapabilities?: () => string[] }` to allow optional chaining. The cast is sound for the current `NarupaProcessManager`, but if the interface evolves and the method signature changes, TypeScript won't catch it at the call site — the cast silences the check. The commit message acknowledges "NarupaProcessManager does not declare it; raw access is TS2339."
**Recommendation:** Add `getAvailableCapabilities?(): string[]` to the `NarupaProcessManager` type/class as an optional method so no cast is needed. This is the correct long-term fix; the cast is a safe short-term bridge.
