## P1 — Fixed Inline

### P1-a · Broken Access Control on `POST /api/quest-proof/decide`

**Commit**: `f32e097c`  
**File**: `packages/studio/src/app/api/quest-proof/decide/route.ts`  
**OWASP**: A01 Broken Access Control

**Issue**: The decide-all route had no server-side authentication gate. Any caller
who could reach the Studio server could POST arbitrary `taskIds` and an unconstrained
`action` string, causing the server to bulk-PATCH board tasks via the HoloMesh API
using the server-side `HOLOMESH_API_KEY`. Three sub-problems:

1. No `getServerSession` check — unauthenticated callers allowed.
2. `action` accepted any string from the request body and forwarded verbatim to the
   upstream board PATCH endpoint (allows triggering `claim`/`open`/`reopen` etc.).
3. `taskId` strings from the request were interpolated directly into the upstream URL
   without sanitization — a value like `../../../other-route` would traverse paths on
   `mcp.holoscript.net` (SSRF variant, constrained to upstream server only).

**Fix applied** (`fix(security): auth gate + action allowlist + taskId sanitization on quest-proof decide/board`):

- Added `getServerSession(authOptions)` → 401 if no `session.user.id`.
- `ALLOWED_ACTIONS = new Set(['done'])` — rejects any non-allowlisted action string.
- `TASK_ID_RE = /^[a-zA-Z0-9_-]+$/` — rejects path-traversal characters in taskIds.
- Test file updated with `vi.doMock('next-auth', …)` pattern + new 401 and 400-action test cases.
