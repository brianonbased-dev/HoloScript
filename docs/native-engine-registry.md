# Native Engine & Renderer Registry

> **What this is.** The tracked inventory of HoloScript's **sovereign** (native) engines, renderers,
> and compile targets — the ones we own end-to-end, that run on our own GPU / DOM / VM path with no
> third-party engine required to execute. Created 2026-06-05 because we *had* these engines but were
> not promoting, building, or tracking them as a set (D.006's sovereign-vs-bridge split was doctrine
> with no backing data structure).
>
> **Machine-readable SSOT:** [`packages/core/src/compiler/sovereign-targets.ts`](../packages/core/src/compiler/sovereign-targets.ts)
> (`SOVEREIGN_TARGETS`, `BRIDGE_TARGETS`, `SOVEREIGN_ENGINES`, `isSovereignTarget`). This doc is the
> human view; the manifest is the source of truth. A compile-time exhaustiveness guard there forces
> every **new** `ExportTarget` to be classified sovereign / bridge / mode — so nothing can stay
> invisible again. Tests: [`sovereign-targets.test.ts`](../packages/core/src/compiler/__tests__/sovereign-targets.test.ts)
> (asserts classification + that every engine file below exists on disk).

## Why "sovereign" matters

A **sovereign** target/engine renders or executes on infrastructure HoloScript owns: our WebGPU
renderer, our bytecode VM, our Rust/WASM front-end, our neuromorphic IR. A **bridge** target emits an
artifact a *third-party* engine consumes (Unity, Unreal, Godot, Babylon, R3F/Three.js, USD, glTF).
Bridges are valuable interop — but the platform's differentiator is the sovereign stack, and that is
the half that was going unpromoted while the third-party engine names led every surface.

## The honest gaps (what "not promoting / building / tracking" meant)

1. **The sovereign renderer is orphaned from the deploy path.** `WebGPURenderer` is a real native GPU
   renderer, but the *deployed* `services/render-service` is a share-link/QR shim (`/embed` returns a
   literal `<h1>`), and Studio/preview still lean on R3F/Three.js bridges. We own a sovereign renderer
   we don't ship to users.
2. **Two native emitters are untested** (`Native2DCompiler`, `Canvas2DGameCompiler`) — REAL but fragile
   under refactor.
3. **No promotion surface names the native set.** The marketing `CompileTargetGrid` leads with
   Unity/Unreal/Godot; FULL_README's sovereign table omits the native 2D pipeline; `render-service`
   has no README.
